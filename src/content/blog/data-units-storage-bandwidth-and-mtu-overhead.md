在计算机与网络通信体系中，存在两套最容易让非专业用户甚至资深工程师产生认知混乱的度量衡常识：

1. **“硬盘缩水之谜”**：花大价钱买来的 1TB 固态硬盘或手机，插到 Windows 电脑里一格式化，容量瞬间只剩“**931 GB**”，甚至一度引发多起集体诉讼；
2. **“千兆宽带缩水之谜”**：运营商办理的“1000 Mbps 千兆光纤”，直觉换算 $1000 \div 8 = 125\text{ MB/s}$，但无论用哪个测速工具或下载软件，速度极限永远被死死按在 **117 ~ 118 MB/s** 左右。

这并不是奸商克扣容量，也不是运营商暗中限速，而是**国际标准制式（SI 十进制）与计算机物理架构（IEC 二进制）的百年标准博弈**，以及**计算机网络从以太网数据链路层到应用层的层层封包物理税**。

本文结合本站[数据存储与带宽换算器](/converters/data/)以及[速度单位换算器](/converters/speed/)的实现原理，带你逐层揭开这一“数字账本”。

## 1. 1TB 为什么变成了 931 GiB？

问题的根源在于：**同一个前缀（Kilo, Mega, Giga, Tera），在硬件厂商和操作系统眼里有着完全不同的数学定义。**

### 两个对立的世界

```text
硬件制造商 (SI 国际单位制, 10 的幂次):
  1 KB = 10³ = 1,000 Bytes
  1 MB = 10⁶ = 1,000,000 Bytes
  1 GB = 10⁹ = 1,000,000,000 Bytes
  1 TB = 10¹² = 1,000,000,000,000 Bytes

计算机底层 (IEC 国际电工委员会标准, 2 的幂次):
  1 KiB = 2¹⁰ = 1,024 Bytes
  1 MiB = 2²⁰ = 1,048,576 Bytes
  1 GiB = 2³⁰ = 1,073,741,824 Bytes
  1 TiB = 2⁴⁰ = 1,099,511,627,776 Bytes
```

- **硬盘与闪存厂商的视角**：采用十进制标准（SI）。当他们生产一块 1TB 的硬盘时，芯片上整整齐齐排布了 $1,000,000,000,000$ 个字节（Byte）。从法律和物理定义上，他们没有缺斤短两；
- **Windows 操作系统的视角**：计算机内部总线、地址指针和寄存器都是基于二进制寻址（$2^{10} = 1024$）。微软 Windows 在计算磁盘容量时，使用 $1024^4$ 来折算，但界面上却极其不严谨地继续使用“GB/TB”作为单位标签，而不是标准的“GiB/TiB”！

### 精确算账

$$\text{Windows 显示容量} = \frac{1,000,000,000,000 \text{ 字节}}{1024 \times 1024 \times 1024 \times 1024 \text{ 字节/TiB}} \approx 0.90949 \text{ TiB}$$

换算为吉字节（GiB）：

$$0.90949 \times 1024 \approx \mathbf{931.32 \text{ GiB}}$$

在标称单位越大的设备上，这种进阶差异越触目惊心：
- **1 KB 时代**：差异仅为 $(1024 - 1000) / 1000 = 2.4\%$；
- **1 MB 时代**：差异扩大至 $4.8\%$；
- **1 GB 时代**：差异扩大至 $7.4\%$；
- **1 TB 时代**：差异扩大至 **$9.09\%$**；
- **1 PB 时代**：差异将直接超过 **$12.5\%$**！

> **趣味常识**：苹果 macOS 自 2009 年的 OS X 10.6（Snow Leopard）起，全面将操作系统文件管理器的容量计算切换为 **十进制（1000 进位）**。因此同一块 1TB 固态硬盘插在 Mac 上会老老实实显示“1.00 TB”，而在 Windows 上则显示“931 GB”。

## 2. 为什么千兆宽带极限下载只有 118 MB/s？

我们常说的“千兆宽带”，运营商标称的速率是 **1000 Mbps**（Megabits per second，兆比特每秒）。
而下载软件显示的速率单位是 **MB/s**（MegaBytes per second，兆字节每秒）。

因为 1 字节（Byte）包含 8 个比特（bit），基础换算如下：

$$\text{理论物理通道极限} = \frac{1000 \text{ Mbps}}{8} = 125 \text{ MB/s}$$

但是，数据从服务器网卡发出，经过光纤抵达你的硬盘，必须经过计算机网络分层体系（OSI 模型）的层层包装。

### 拆解以太网帧的“每一粒米”

在经典的以太网（Ethernet v2）与 IPv4 环境下，每一个网络传输包的解剖图如下：

```text
┌─────────────────────────────────────────────────────────────┐
│ 物理层前导码与帧间隔 (Preamble + SFD + IPG)        20 字节  │
├─────────────────────────────────────────────────────────────┤
│ 链路层以太网帧头 (Ethernet Header: MAC源/目标/Type) 14 字节  │
├─────────────────────────────────────────────────────────────┤
│ 网络层 IP 协议头 (IPv4 Header)                     20 字节  │
├─────────────────────────────────────────────────────────────┤
│ 传输层 TCP 协议头 (TCP Header，含时间戳选项)         32 字节  │
├─────────────────────────────────────────────────────────────┤
│ 应用层有效载荷 (TCP Payload / MSS)                 1448 字节 │
├─────────────────────────────────────────────────────────────┤
│ 链路层帧校验码 (Frame Check Sequence, FCS/CRC)      4 字节  │
└─────────────────────────────────────────────────────────────┘
```

1. **标准 MTU（最大传输单元）** 为 **1500 字节**；
2. 扣除 IPv4 头部（20 字节）与标准带时间戳选项的 TCP 头部（32 字节）后，留给你的纯文件的有效载荷大小（MSS, Maximum Segment Size）只有：
   $$\text{MSS} = 1500 - 20 - 32 = \mathbf{1448 \text{ 字节}}$$
3. 但是在物理网线上，为了发送这 1500 字节的包，硬件必须额外附加：
   - 以太网报头（14 字节）+ CRC 校验（4 字节）= 18 字节；
   - 物理层前导同步码（Preamble 7 字节 + SFD 1 字节）= 8 字节；
   - 帧间隙（Inter-Packet Gap, IPG 最小 96 bit-time）= 12 字节；
   - **单帧占用的实际物理介质总开销** = $1500 + 18 + 8 + 12 = \mathbf{1538 \text{ 字节}}$！

### 传输效率终极推导

纯数据有效载荷与线缆总开销的比率：

$$\eta_{\text{Ethernet}} = \frac{1448 \text{ 字节}}{1538 \text{ 字节}} \approx \mathbf{94.15\%}$$

将千兆线路的 125 MB/s 乘以该效率：

$$\text{TCP 传输层理论极限} = 125 \text{ MB/s} \times 94.15\% = \mathbf{117.68 \text{ MB/s}}$$

如果再加上：
- **TLS 1.3 加密记录头（Record Overhead）**：每 16 KB 数据额外消耗 20 字节；
- **HTTP/2 帧头**：每个数据帧 9 字节；
- **TCP ACK 反向确认流量微小挤占**与光纤传输误码微小重传；

**在实际千兆家用宽带下，下载速度能够稳定在 114 ~ 118 MB/s 之间，就已经是达到了物理学与协议栈极限的满速状态！**

## 3. 批量大数据传输的工程预估公式

在规划大数据同步、全量数据库迁移或大规模视频资源分发时，工程师往往需要精确测算“传完这批数据到底需要多久”。

千万不要用简单的 `数据总量 / 标称带宽`，一个严密的工程估算模型应该考虑如下变量：

$$T_{\text{total}} = T_{\text{handshake}} + \frac{S \times (1 + \alpha)}{\min(B_{\text{upload}}, B_{\text{download}})} + \text{RTT} \times \left\lceil \log_2 \frac{\text{BDP}}{\text{IW}} \right\rceil$$

其中：
- $S$：待传输文件的净字节数；
- $\alpha$：协议栈封包损耗系数（常规 HTTPS 取 $1.06 \sim 1.08$，含协议头与 TLS 开销）；
- $B$：瓶颈带宽（需取发送端上行与接收端下行的最小值）；
- $\text{RTT}$：往返延迟（跨国传输可能高达 180ms，TCP 慢启动阶段会额外消耗数个 RTT 才能拉满窗口）；
- $\text{BDP}$：带宽时延积（Bandwidth-Delay Product）。
